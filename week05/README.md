1. 무엇이 위험했는지  
    API_KEY와 DB_URL이 그대로 외부에 노출되어 다른 사람이 악의적으로 이용할 위험이 있었다.

2. 어떻게 고쳤는지  
    .env 파일을 생성해 API_KEY와 DB_URL 등의 정보를 옮기고 load_dotenv 메서드를 통해 .env 파일 내용을 읽어와 api카를 사용했다.

3. 만약 실키가 1차 커밋으로 노출되었다면 올바른 대응 절차는 무엇인지  
    1. 노출되었다는 사실을 인지한 즉시 해당 키를 폐기한다.  
    2. 새 키는 .env 파일에 저장하고 .gitignore에 .env 파일이 포함되어 있는지 다시 확인한다.
    3. 악용되지 않았는지 사용량, 청구 내역을 확인하고 악용되었다면 관계자들에게 알리고 신고한다.
    4. 필요하다면 git filter-repo 등을 통해 과거 커밋된 내용에서 .env 파일을 모두 지운다.
