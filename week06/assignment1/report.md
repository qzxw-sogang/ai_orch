# 프롬프트 3기법 비교 리포트
## 1. 과업 정의

- 선택: (가) 문의 분류  

- 분류 항목: 주문 / 배송 / 환불 / 제품문의 / 기타  

- 긴급도 기준  
    - 긴급도 3: 주문, 배송과 관련해 빠른 시간 내에 처리해야하는 문제
    - 긴급도 2: 환불과 관련해 상황을 확인한 후 처리해야하는 문제
    - 긴급도 1: 제품 문의, 기타 등 언제든지 답변 가능한 간단한 문제

- 명확성 기준
    - 명확: 문의 내용이 일관성 있고 분류와 일치하는 경우
    - 애매: 명확한 경우를 제외한 나머지 경우

- 이유: 문의의 긴급도와 명확성을 판단한 핵심적인 이유를 서술

- 출력 형식: {"분류 항목": "주문|배송|환불|제품문의|기타", "긴급도": 1~3 정수, "명확성": "명확|애매", "이유": "..."}

## 3. 프롬프트 전문
### Zero-shot
고객 문의: ...
이 문의를 아래 기준에 맞춰서 분류해서 결과를 출력해줘
- 분류 항목: 주문 / 배송 / 환불 / 제품문의 / 기타  

- 긴급도 기준  
    - 긴급도 3: 주문, 배송과 관련해 빠른 시간 내에 처리해야하는 문제
    - 긴급도 2: 환불과 관련해 상황을 확인한 후 처리해야하는 문제
    - 긴급도 1: 제품 문의, 기타 등 언제든지 답변 가능한 간단한 문제

- 명확성 기준
    - 명확: 문의 내용이 일관성 있고 분류와 일치하는 경우
    - 애매: 명확한 경우를 제외한 나머지 경우

- 이유: 문의의 긴급도와 명확성을 판단한 핵심적인 이유를 서술

- 출력 형식: {"분류 항목": "주문|배송|환불|제품문의|기타", "긴급도": 1~3 정수, "명확성": "명확|애매", "이유": "..."}

### Few-shot
고객 문의: ...
이 문의를 아래 기준에 맞춰서 분류해서 결과를 출력해줘
- 분류 항목: 주문 / 배송 / 환불 / 제품문의 / 기타  

- 긴급도 기준  
    - 긴급도 3: 주문, 배송과 관련해 빠른 시간 내에 처리해야하는 문제
    - 긴급도 2: 환불과 관련해 상황을 확인한 후 처리해야하는 문제
    - 긴급도 1: 제품 문의, 기타 등 언제든지 답변 가능한 간단한 문제

- 명확성 기준
    - 명확: 문의 내용이 일관성 있고 분류와 일치하는 경우
    - 애매: 명확한 경우를 제외한 나머지 경우

- 이유: 문의의 긴급도와 명확성을 판단한 핵심적인 이유를 서술

- 출력 형식: {"분류 항목": "주문|배송|환불|제품문의|기타", "긴급도": 1~3 정수, "명확성": "명확|애매", "이유": "..."}

- 예시: 
| 예1 | 주문할 때 사은품 옵션 선택을 빼먹었어요. 지금이라도 추가할 수 있을까요? | 주문 | 3 | 명확 | 주문 내용 수정 요청 하나뿐이라 '주문'에 해당함. 출고 전에 반영해야 하므로 빠른 처리가 필요함 |
| 예2 | 내일 아침 출국이라 오늘 안에 꼭 받아야 해요. 지금 배송이 어디까지 왔는지 알려주세요. | 배송 | 3 | 명확 | 배송 위치 확인 요청으로 '배송'에 해당함. 오늘 안이라는 시한이 있어 빠른 처리가 필요함 |
| 예3 | 소파 배송일이 한 달 뒤로 밀렸다고 연락받았어요. 그렇게까지는 못 기다리니 환불해 주세요. | 환불 | 2 | 애매 | 원인은 배송 지연(배송)이지만 실제 요청은 환불이라 문의 내용과 분류가 하나로 맞아떨어지지 않음. 요청 기준으로 환불로 분류함 |
| 예4 | 이 전기포트는 용량이 몇 리터이고, 물 끓는 데 보통 몇 분 걸리나요? | 제품문의 | 1 | 명확 | 제품 사양에 대한 단순 질문으로 '제품문의'에 해당함. 언제 답변해도 문제없음 |
| 예5 | 적립금 유효기간이 언제까지인지 확인하고 싶어요. | 기타 | 1 | 명확 | 주문·배송·환불·제품 어디에도 속하지 않는 계정/혜택 문의라 '기타'에 해당함. 급하지 않은 단순 확인임 |

### CoT  
당신은 온라인 쇼핑몰의 고객 문의 분류기입니다.
아래 [분류 기준]에 따라 [문의]를 분류하세요. 반드시 [추론 단계] 순서대로 추론을 먼저 쓰고, 마지막 줄에는 JSON 한 줄만 쓰세요.

[분류 기준]
- 분류 항목: 주문 / 배송 / 환불 / 제품문의 / 기타 중 하나만 고른다.
- 긴급도 (1~3 정수)
  - 3: 주문, 배송과 관련해 빠른 시간 내에 처리해야 하는 문제
  - 2: 환불과 관련해 상황을 확인한 후 처리해야 하는 문제
  - 1: 제품 문의, 기타 등 언제든지 답변 가능한 간단한 문제
- 명확성
  - 명확: 문의 내용이 일관성 있고 분류와 일치하는 경우
  - 애매: 명확한 경우를 제외한 나머지 경우

[추론 단계]
1단계: 고객이 실제로 요청하는 행동이 무엇인지 쓴다. 문제의 원인과 요청이 다르면 요청을 기준으로 삼는다. 반어적 표현이면 글자 그대로가 아니라 실제 의도를 쓴다.
2단계: 1단계의 요청에 맞는 분류 항목 하나를 고른다.
3단계: 2단계의 분류 항목과 긴급도 기준을 대조하여 긴급도를 정한다.
4단계: 명확성을 판정한다. 다음 중 하나라도 해당하면 애매로 판정한다.
  - 원인과 요청이 서로 다른 분류에 해당함
  - 표면적 의미와 실제 의도가 다름(반어법)
  - 두 가지 이상의 화제가 섞임
  - 문장이 짧거나 정보가 부족해 분류가 둘 이상으로 갈릴 수 있음
  해당 사항이 없으면 명확으로 판정한다.
5단계: 마지막 줄에 아래 [출력 형식]의 JSON을 쓴다.

[출력 규칙]
1. 각 단계는 "1단계:"처럼 시작하고 1~2문장으로 짧게 쓴다.
2. 마지막 줄은 JSON 한 줄만 쓴다. JSON 앞뒤에 다른 글자, 설명, 인사말을 붙이지 않는다.
3. 마크다운(코드블록 ```, 굵게 **, 제목 #)을 사용하지 않는다.
4. JSON의 키와 문자열 값은 큰따옴표(")로 감싸고, 긴급도는 따옴표 없는 정수로 쓴다.
5. "이유"에는 긴급도와 명확성을 판단한 핵심 근거를 한 문장으로 쓴다.

[출력 형식]
{"분류 항목": "주문|배송|환불|제품문의|기타", "긴급도": 1~3 정수, "명확성": "명확|애매", "이유": "..."}

[문의]
문의 내용: {문의 내용}

## 6. 분석

- 형식 준수: Zeroshot과 Fewshot기법에서는 일부 사례에서 코드펜스로 인해 파싱이 어려운 경우가 생겨 형식이 준수되지 않는 경우가 존재했다. 하지만 CoT는 출력 규칙을 통해 코드펜스와 같은 부분을 없애고 모든 경우에서 마지막 줄만 파싱하면 되므로 형식을 준수했다고 판단할 수 있다.

- 분류 정확성: 명확 사례에서는 기법간 차이점이 거의 없었다. 애매(4, 5번) 사례에서는 Zeroshot 기법은 모두 정답을 맞추지 못했다. 이를 통해 Zeroshot 기법이 다른 기법에 비해 정답률이 떨어지다는 게 확인됐다. 특히 5번 사례에서는 모든 기법이 첫 시도에는 정답을 맞추지 못하였는데 CoT의 경우 세 번째 시도에 정답을 맞췄다. 이를 통해 CoT가 제일 정답을 맞출 가능성이 높은 기법이라는 것을 확인할 수 있었다.

- 일관성: 5번 사례를 보면 Zeroshot, Fewshot 기법은 반복된 시도에도 일관된 맥락에 따라 답변을 해주었다. 마찬가지로 5번 사례에서 CoT는 대체로 일관성이 있는 답변을 해주지만 경우에 따라 답변이 달라지기도 한다.

- 비용: 위 실험에서는 비용에 대한 분석을 진행하지 않았지만 원론적인 수준에서 답변하자면 Zeroshot기법은 한번 프롬프트를 작성하면 예시의 수에 상관없이 입력 토큰이 일정하다. Fewshot은 예시 수만큼 입력 토큰이 늘어나게 된다. CoT는 입력은 일정하지만 출력 과정에서 답변 과정에서 일어날 추론의 양을 사전에 예측할 수 없고 문제가 복잡할수록 추론이 길어지기 때문에 출력 토큰이 다른 기법에 비해 많이 사용되고 변동성이 크다.

## 7. 결론 — 우리 팀이 쓸 기본 전략

Fewshot이 CoT에 비해 비용은 적지만 Zeroshot에 비해 정확성이 높은 절충적인 기법으로 판단되어 Fewshot을 기본적으로 사용할 것이다.
